02.1Procedural vs Object-Oriented Programming

Procedural ProgrammingObject-Oriented Programming
Organized around Functions that operate on data Objects that bundle data + the functions that act on it
Data Usually global/shared, passed around freely Owned by an object, access controlled
Grows into Long call chains, hard to isolate change Independent units (classes) you can change one at a time
Definition worth memorizing

OOP is a programming paradigm that organizes software design around data (objects) rather than functions — each object bundles its own data and the behavior that acts on that data, instead of scattering that data through independent functions.

PillarOne line
AbstractionShow what an object does, hide how it does it.

02.3Abstraction

Abstraction means exposing only the essential features of an object and hiding the internal complexity of how it works.

Driving analogy

A driver uses the steering wheel, the accelerator, and the brake. They don't need to know how the engine combusts fuel or how the gearbox shifts ratios to drive the car — that complexity is abstracted away behind a simple interface.

Fig 2.1 — the driver only ever calls the top row; the bottom row is abstracted away

Car class — abstraction in code

In C++, abstraction is usually built with a small public interface calling into a larger private implementation:

class Car {
private:
    bool engineOn;
    int gear;
    int fuelLevel;

    // internal details the driver never touches directly
    void engineIgnite() {
        engineOn = true;
    }
    void shiftGear(int newGear) {
        gear = newGear;
    }
    void fuelInjection() {
        fuelLevel -= 1;
    }

public:
    // this is the ONLY surface the driver interacts with
    void start() {
        engineIgnite();
        std::cout << "Car started
";
    }

    void accelerate() {
        shiftGear(gear + 1);
        fuelInjection();
    }

    void brake() {
        shiftGear(gear - 1);
    }
};

int main() {
    Car myCar;
    myCar.start();         // driver calls simple methods...
    myCar.accelerate();
    // myCar.engineIgnite();  would not compile -- it's private
}
Interview answer

"Abstraction is a design-level concept — it's about what you choose to expose in the interface (start(), accelerate()) versus what you keep as implementation detail (engineIgnite(), fuelInjection()), so the caller only ever thinks in terms of what the object can do."

02.4Encapsulation

Encapsulation means bundling data and the methods that operate on that data into a single unit (a class), and controlling access to that data from outside — usually by making fields private and exposing controlled public getters/setters.

Fig 2.2 — data hiding: the outside world never sets fuelLevel directly

Encapsulation in code

class Car {
private:
    int fuelLevel;   // hidden -- can't be set to a garbage value from outside
    int speed;

public:
    Car() : fuelLevel(0), speed(0) {}

    // controlled read access
    int getFuel() const {
        return fuelLevel;
    }

    // controlled write access -- validation lives HERE, in one place
    void refuel(int amount) {
        if (amount > 0)
            fuelLevel += amount;
    }
};

int main() {
    Car myCar;
    myCar.refuel(20);
    // myCar.fuelLevel = -50;   would not compile -- fuelLevel is private
    std::cout << myCar.getFuel();
}
Why this matters, not just syntax

Without encapsulation, any part of a large codebase could set fuelLevel = -999 directly. With it, refuel() is the only door in, so every validation rule lives in exactly one place. That is the maintainability pillar from Lecture 01, in practice.

02.5Abstraction vs Encapsulation — the distinction interviewers probe

AbstractionEncapsulation
LevelDesign level ("what should the outside world see?")Implementation level ("how do I protect the data?")
SolvesComplexity — hides unnecessary detailData integrity — hides unsafe direct access
How, in C++Designing a small public method surface (sometimes with abstract classes/interfaces)Access specifiers (private/protected) + getters/setters
One-liner"You don't see the engine.""You can't reach in and rewire the engine even if you wanted to."
